# Oturum sözlüğü: Altyapı, Performans, Maliyet ve Değerlendirme

[Oturuma dön](README.md) | [English](glossary.md) | [2026 Donanım Referansı](donanim-referansi-2026.md) | [Genel sözlük](../../docs/tr/kavram-sozlugu.md)

> **Canlı ders öncesi 5 dakikalık ön okuma:** Oturum 05'te **`G4 / H100`**, **`L4`** ve **`T4`** katmanlarının tamamında aynı **`Gemma 4 12B QAT + MTP`** modelini elma-elma (*apples-to-apples*) koşturup çıkarım hızını, KV önbelleğini, enerji/maliyet ekonomisini, tracing izlerini ve eval puanlarını ölçüyoruz.

| Terim | Bu oturumdaki anlamı ve dersteki rolü |
| --- | --- |
| `Inference` | Eğitilmiş bir modelin ağırlıklarını kullanarak kullanıcı istemini işleyip (`Prefill`) yeni tokenlar üretme (`Decode`) süreci (`5.1`). |
| `Chunked Prefill (GEMM)` | Uzun kullanıcı istemini `--ubatch-size` dilimlerine (`64..512`) bölüp matris-matris çarpımıyla (`[B × d] × W`) tek geçişte KV önbelleğini dolduran, **compute-bound** (Tensor Core doyuran) ilk aşama (`5.1`, `Deney 1`). |
| `Decode (GEMV & Memory Wall)` | Her adımda yalnız 1 yeni token için (`[1 × d] × W`) tüm model ağırlıklarını HBM/VRAM'den okuyan matris-vektör aşaması; hesaplama yerine bellek bant genişliğine takılır (**Memory Wall**: $\text{Max tok/s} \approx \text{BW} / \text{Aktif Ağırlık}$) (`5.1`, `Deney 1`). |
| `Roofline Model` | Bir işlemin GPU'da bellek bant genişliği sınırında mı (*memory-bound* — saf decode) yoksa FLOPS hesaplama sınırında mı (*compute-bound* — prefill / büyük batch) kaldığını gösteren tavan modeli (`5.1`). |
| `Continuous Batching` | Eşzamanlı kullanıcı (`N`) isteklerinin token adımlarını iterasyon bazında birleştirip `[1 × d]` GEMV işlemini `[N × d]` GEMM'e dönüştürerek GPU kullanımını ve toplam `tok/s` verimini katlayan zamanlama (`5.1`, `5.3`). |
| `HBM vs On-Chip SRAM` | Yüksek kapasiteli ancak görece dar kapılı ana çip belleği (**HBM3/HBM3e/HBM4**: `3,35–23,3 TB/s`) ile hesaplama çekirdeklerinin hemen içindeki ultra hızlı ama küçük yerel bellek (**SRAM**: GPU L1/shared memory / TPU `Vmem` / Cerebras `44 GB` wafer SRAM: `43,2 PB/s`) ayrımı (`5.1`). |
| `Wafer-Scale (WSE-3 / WSE-3T)` | Cerebras'ın 300 mm silikon plakasını bölmeden `44 GB` **on-chip SRAM** ve `900.000` çekirdekle tek çip olarak kullanması; HBM duvarını aşarak `GPT-5.6 Sol Ultrafast ~750 tok/s` gibi hızlara çıkarken yoğun ön-eğitimde GPU kümelerine göre daha düşük FLOPS/$ yoğunluğu sunan mimari (`5.1`). |
| `Quantization (FP16 / FP8 / NVFP4 / Q4_0)` | Ağırlık ve KV tensörlerini 16-bit yerine 8-bit veya 4-bit biçimlerde tutarak bellek duvarı okumalarını küçültme ve uyumlu donanımda hız/kapasite kazanma yöntemi (`5.1`, `5.5`). |
| `TTFT & TPOT` | **Time to First Token (`TTFT`)**: İstem gönderiminden ilk çıktı tokenına kadar geçen prefill+kuyruk gecikmesi (ms); **Time Per Output Token (`TPOT`)**: Ardışık decode tokenları arasındaki ortalama süre (`ms/tok`, tersi `tok/s`) (`5.1`, `Deney 1`). |
| `KV Cache` | Prefill ve önceki turlarda hesaplanan Key/Value tensörlerini bellekte saklayıp sonraki her decode adımında tekrar hesaplamaktan kurtaran önbellek; mimariye göre `768 KB/tok` (klasik 48L FP16 MHA) → `4 KB/tok` (`Gemma 4 12B FP8`) → `890 B/tok` (`DeepSeek-V4.1-Flash`) aralığında değişir (`5.2`, `Deney 1`). |
| `GQA & Sliding Window Attention (SWA)` | Birden fazla Q başlığının daha az sayıda KV başlığını paylaşması (**Grouped-Query Attention**) ve yerel katmanların yalnız son `1024` tokenlık pencereyi (`n_swa=1024`) tutması; `Gemma 4 12B`'de 40 sliding + 8 global (`K=V`) katmanıyla KV belleğini dramatik düşürür (`5.2`). |
| `Prefix Caching (cache_prompt=True)` | Sistem istemi, araç şemaları ve paylaşılan konuşma geçmişinin KV bloklarını yeniden kullanıp `Cold Prefill` yerine `Warm Cache Hit` üreterek `TTFT`'yi düşüren mekanizma; `DualLayerSessionStore` (GPU VRAM + host RAM `--cache-ram`) ile desteklenir (`5.2`, `Deney 2`). |
| `3'lü Cache Miss (L4 Vakası)` | `enable_thinking=False` şablonunda `3` token sola kayma, `SWA 1024` nedeniyle `--cache-reuse` kapanması ve `--parallel 2` `slot_prompt_similarity=0.1` + sabitlenmemiş `id_slot` çakışmasının birleşip `Cached: 0` üretmesi (`5.2`). |
| `Speculative Decoding (MTP & DFLASH)` | Küçük taslak başlığının birden çok aday token üretip ana modelin bunları tek mini-GEMM geçişinde kayıpsız doğrulaması: **MTP** (ardışık taslak — tek kullanıcı *ve* çok kullanıcılı continuous batching'de çalışır) ve **DFLASH** (Block Diffusion: 1 paralel ileri geçişte 8–16 taslak token üretip tek adımda doğrular) (`5.1`). |
| `MoE (Active vs Total Params)` | **Mixture of Experts**: Toplam parametre sayısı büyük olsa da (ör. `Gemma 4 26B A4B` toplam `26B`) her token için yalnız küçük bir uzman alt kümesini (`4B` aktif) çalıştırarak decode bellek trafiğini sınırlayan mimari (`5.5`). |
| `CED & CSA2` | **DeepSeek-V4.1-Flash** mimarisinde KV sıkıştırma ve bellek erişim yükünü `890 B/tok` (FP4 KV ile `1M` bağlamda `< 0,9 GB`) düzeyine indiren gelişmiş dikkat ve bağlam kodlama teknikleri (`5.2`, `5.5`). |
| `$/1M Token & Joule/Token` | AI Factory ekonomi ve enerji metrikleri: $\text{Maliyet/1M} = (\text{Saatlik Ücret} / (\text{tok/s} \times 3600)) \times 10^6$ ve $\text{Joule/Token} = \text{Watt} / \text{tok/s}$ (`T4 ~2,33 J/tok` vs `G4 8-slot ~0,46 J/tok`) (`5.3`, `Deney 2`). |
| `Observability & Tracing` | Sunucu `/metrics` sayaçları, `timings` yanıt alanları, anlık `nvidia-smi` `power.draw` okuması ve adım bazlı **Span Tree** (`llm_prefill`, `llm_decode`, `tool_exec`) kayıtlarıyla üretim davranışını izleme (`5.4`, `Deney 3`). |
| `Evals (Det. / Trajectory / Judge)` | Deterministik olamayan ajan sistemlerini 3 katmanda ölçme: **Deterministik** (JSON Şema/araç/çıktı doğrulama), **Trajectory** (adım sırası ve araç seçim yolu) ve **LLM-as-a-Judge** (yanıt kalitesi puanlaması — uzunluk/konum yanlılığına dikkat edilerek) (`5.5`, `Deney 3`). |
| `Artificial Analysis Pareto` | Modelleri Zeka/Kalite skoru karşısında **Fiyat (`$/1M`)**, **Hız (`tok/s`)** ve **Gecikme (`TTFT`)** Pareto sınırında konumlayarak iş yüküne uygun mimari seçme çerçevesi (`5.5`). |
| `Code Mode (Programmatic Tool Calling)` | **Müfredat dışı ek (Bonus):** Binlerce `MCP`/API şeması (`~1,17M` token) ve tekrar eden `N+1` araç turu yerine modele `search()` + `execute()` verip toplu (*batched*) çağrıları V8 Isolate (Cloudflare) veya sandbox'ta (Anthropic `PTC`) kod olarak çalıştırma deseni (`%90–99` token tasarrufu). |
