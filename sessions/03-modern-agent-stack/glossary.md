# Session glossary: Modern Agent Stack

[Back to session](README.en.md) | [Türkçe](kavram-sozlugu.md) | [General glossary](../../docs/en/glossary.md)

> **5-minute pre-read before the live workshop:** Skim these 30 terms ahead of class—you do not need to memorize them. They map directly to what you will watch on screen as we move from a single-agent harness (`02`) to `MCP` tool discovery, deterministic gates, multi-agent `StructuredHandoff`, and the full modern stack from `System 1` decision primitives (`Jev` and open-weight `Laya`) to `llama.cpp v1.0.0` `1M+`-KV-pooled natively multimodal `Gemma 4 12B`, `World Models`, and the live `mistral-vibe` `Agentic CLI` (`E1`–`E2`).

| Term | Meaning in this session and role in the lesson |
| --- | --- |
| `MCP` | Open integration protocol (Model Context Protocol) that lets agent applications discover and invoke tools and resources through standard messages; here `InProcessMCPServer` hosts `campus_kb`, `ops_desk`, and `media_world` (`A1`). |
| `JSON-RPC 2.0` | Lightweight request-response envelope format used inside `MCP` for `initialize`, `tools/list`, and `tools/call` messages (`4B`, `A1`). |
| `Tool discovery` / `Dynamic tool binding` | Querying available tools at runtime via `tools/list` instead of hard-coding capabilities up front, and attaching discovered tools (such as `mcp__campus_kb__search_docs`) strictly within an agent's allowed plugin scope (`4B`, `A1`, `C1`). |
| `Plugin` | A packaged capability module exposing executable tools under a namespace; here `campus_kb` (read-only knowledge base), `ops_desk` (lab slot operations), and `media_world` (T4-compatible mockup of diagram generation and capacity simulation) are three separate plugins (`A1`–`A2`, `D2`). |
| `Skill` | A procedural instruction bundle describing the workflow steps and constraints for a task (`policy-qa`, `lab-ops`, `incident-triage`, `visual-sim` in `SKILL_LIBRARY`, plus `quota-audit/SKILL.md` in `E2`); guidance, not executable code (`A2`, `E2`). |
| `Progressive disclosure` | Keeping only a compact skill catalog in initial context and loading full procedural instructions (`render_skill_context`) only for the selected active skill (`A2`). |
| `Multi-agent orchestration` | Coordinating an orchestrator and focused specialist agents so a complex task completes inside clear tool and step boundaries (`4E`, `C1`–`C3`). |
| `Orchestrator / coordinator` | The top-level controller (`ModernOrchestrator`) that runs the deterministic gate, invokes `System1DecisionGate`, and dispatches work within `max_handoffs=2`. |
| `Specialist agent` | A scoped subagent restricted to its own domain and allowed plugins; `research_specialist` sees only `campus_kb`, `operations_specialist` sees only `ops_desk`, and `simulation_specialist` sees only `media_world` (`C1`, `D2`). |
| `Routing` | Choosing the right execution path for a request—deterministic gate, `direct_system1` reflex, or a specific specialist agent (`B1`, `C1`, `D2`). |
| `Delegation` | Assigning a bounded subtask from a coordinator to a worker under an explicit role and tool scope (`4E`, `C1`). |
| `Handoff` | Transferring active task control to another agent; unvalidated handoffs risk loops or dropped constraints (`C2`–`C3`). |
| `Structured handoff` | A schema-validated JSON handoff (`target_specialist`, `active_skill`, `user_goal`, `constraints`, `complexity`) that preserves requirements and rejects unlisted targets such as `admin_agent` (`C2`–`C3`). |
| `Context loss` | Losing critical user constraints such as `"T4"` or `"14:00"` during an unstructured (`lossy`) free-text handoff, causing downstream errors (`C2`). |
| `Rule-based / deterministic gate` | A Python pre-check (`deterministic_gate`) that handles bounds checks, `TR-204` ticket lookups, or exact `4 saat * 12.5 CU` math at `0` tokens and `0` LLM calls (`B1`). |
| `Hybrid workflow` | Using an LLM to interpret free text or extract parameters while Python validates inputs, checks permissions, and computes exact arithmetic or slot state (`B2`). |
| `System 1 decision model (Jev)` | Inspired by Kahneman's fast-reflex System 1 and TypeSafe AI's closed-source `Jev` paradigm: a **non-autoregressive** decision layer returning typed primitives in a single forward pass; `System1DecisionGate` in the notebook is a lightweight T4-compatible mockup of this contract (`D1`–`D3`). |
| `Laya (Apache-2.0 System 1 model)` | An open-weight (**Apache-2.0**-licensed, **~100M-parameter** encoder-based) non-autoregressive System 1 decision model family serving as an open counterpart to `Jev`, returning `Choice`, `Score`, and `Noul` primitives with zero syntax hallucination (`D1`–`D3`). |
| `Choice` / `Score` / `Noul` (`RLCD`) | Three `System 1` decision primitives (`Jev` / `Laya`): `Choice` picks from a closed option set, `Score` outputs a rubric score (including *Jev-Mem* memory scoring), and `Noul` outputs a calibrated `[0, 1]` probability trained via **RLCD** (*Reinforcement Learning for Calibrated Decisions*) (`D1`, `D3`). |
| `SLM (Small Language Model)` | A compact autoregressive language model suited to low-latency edge or local text tasks (such as `Qwen3.5-0.8B` in session 1); faster than large LLMs, yet still distinct from non-autoregressive System 1 decision gates. |
| `System 2 / reasoning model` | A deeper reasoning tier reserved for multi-step tool execution, policy synthesis, and complex constraint solving; here `Gemma 4 12B QAT + MTP` on `llama.cpp v1.0.0` (`b12359`) with `1.0 / 0.95 / 64` sampling, target+draft `f8_e4m3` KV (`-ctkd/-ctvd`, `p_min=0.75`), `262,144` max active context, and a `1,048,576` total KV pool plays this role (`D1`–`E2`). |
| `Multimodal LLM (VLM / Omni)` | A model class able to perceive images, screenshots, PDF pages, audio, or video directly and emit tool calls (`Computer Use` foundation); **`Gemma 4 12B`** is natively multimodal (its text GGUF runtime is used in this lightweight lab to preserve T4 VRAM). |
| `Image / video generation model` | A generative specialist (diffusion / *flow matching*, such as `Qwen-Image`) synthesizing visual diagrams or video frames; orchestrated behind `MCP` tools (`media_world` T4-compatible mockup here) with heavy synthesis left to high-VRAM G4/local setups (`D2`). |
| `World model` | A model or simulator predicting how a physical, spatial, or operational environment changes after an action; represented here via `media_world`'s T4-compatible `simulate_lab_capacity` mockup contract (`D2`). |
| `Agentic CLI (uv + Python 3.14 + mistral-vibe)` | A terminal-native agent harness operating on real files and shell commands; `E1`–`E2` provision SHA-256-verified `uv 0.13.8` + relocatable `/tmp/agentlab-s03-py314` CPython `3.14` (`py314-vibe-env.tar.gz` under `MyDrive/AgentLab-Agent-Runtime` shared `setup`) + `mistral-vibe 3.1.2` (`AGENTS.md` + `SKILL.md`, `1.0 / 0.95 / 64`, `outside_workdir="deny"`), while `hermes-agent`, `gptme`, and `fast-agent-mcp` can attach over `127.0.0.1`. |
| `DualLayerSessionStore (input_cache / output_tokens + KV fallback)` | Fallback-aware session store in `E3`: Layer 1 writes human-readable `transcript.md`, `session_meta.json`, and `session_tokens.jsonl` separating `input_cache` (`cached_prefix_tokens`/`new_input_tokens`) from `output_tokens` (`generated_tokens`/`token_ids`), while Layer 2 saves optional FP8 `slot0.kv.bin` and automatically falls back to Layer 1 replay (`text_replay_fallback`) if `/slots/0?action=restore` fails or mismatches. |
| `AgentWebServer (Colab Web Chat Frame)` | Loopback (`127.0.0.1`) HTTP gateway in `E4`–`E5` serving a Python-Harness-controlled web chat UI via `serve_kernel_port_as_iframe` / `serve_kernel_port_as_window` with `X-AgentLab-Token` authentication instead of an intimidating raw terminal popup or bare `llamaUI` bypassing the harness (and never exposing `llama-server` Bearer keys to the browser). |
| `Model cascade` | Passing requests through the `0`-token `deterministic_gate`, then `System1DecisionGate`, and escalating only complex or low-confidence tasks to `Gemma 4 12B + MTP` (`D2`). |
| `Fallback / escalation` | Recovering safely when `Noul` confidence drops below threshold (`< 0.75`) or a router payload is malformed by setting `escalated_to_system2=True` and escalating to System 2 (`D3`). |
| `Least-privilege tool scope` | Granting each specialist only the plugin tools required for its role; `research_specialist` cannot reserve slots, and injected `admin_agent` commands in `untrusted-ticket` never gain authority (`C1`, `C3`). |
| `KV cache quantization (f8_e4m3 / FP8 vs q8_0)` | Compressing key/value attention memory to fit long context in VRAM; on `llama.cpp v1.0.0`, both target and **draft (`-ctkd/-ctvd`)** use `f8_e4m3` (`--spec-draft-p-min 0.75`, `draft_max` T4 `2` / L4-A100-G4 `3`) — live G4 `1M` GPU KV hit `235.35 tok/s` in `21,279 / 97,887 MiB` VRAM, while earlier T4 `b12359` baseline fit `524,288` (`512K`) GPU KV in `14,047 MiB` VRAM at `41.69 tok/s`, whereas `q8_0` collapses 15x to `2.74 tok/s` even at `65,536`. |
| `Unified 1M+ KV pool & prompt caching (--kv-unified, --cache-reuse)` | Pairing `MAX_CONTEXT=262,144` with `--kv-unified --kv-unified-per-slot 262144`, `--cache-ram`, `--ctx-checkpoints 8`, `--cache-reuse 64`, and `cache_prompt=True` for a **`1,048,576+` (`1M+`) total KV pool** (`1,048,576` GPU KV @ `80.11%` MTP verified live on G4; `524,288` `512K` GPU KV + RAM cache on L4 and T4; live T4 Turn-2 `cached_tokens=182`, `324.07 tok/s` prefill). |
