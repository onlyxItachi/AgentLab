# Session glossary: Modern Agent Stack

[Back to session](README.en.md) | [Türkçe](kavram-sozlugu.md) | [General glossary](../../docs/en/glossary.md)

> **5-minute pre-read before the live workshop:** Skim these terms ahead of class—you do not need to memorize them. They map directly to what you will watch on screen as we move from a single-agent harness (`02`) to `MCP` tool discovery, deterministic gates, multi-agent `StructuredHandoff`, `System 1` decision primitives (`Jev` and open-weight `Laya`), `llama.cpp v1.0.0` `1M+`-KV-pooled natively multimodal `Gemma 4 12B`, `World Models`, dual-layer `DualLayerSessionStore` persistence, and the portless **Studio v2** `Canlı Stüdyo`.

| Term | Meaning in this session and role in the lesson |
| --- | --- |
| `MCP` | Open integration protocol (Model Context Protocol) that lets agent applications discover and invoke tools and resources through standard messages; here `InProcessMCPServer` hosts `campus_kb`, `ops_desk`, and `media_world` (`Deney 1`). |
| `JSON-RPC 2.0` | Lightweight request-response envelope format used inside `MCP` for `initialize`, `tools/list`, and `tools/call` messages (`Deney 1`). |
| `Tool discovery` / `Dynamic tool binding` | Querying available tools at runtime via `tools/list` instead of hard-coding capabilities up front, and attaching discovered tools (such as `mcp__campus_kb__read_doc`) strictly within an agent's allowed plugin scope (`Deney 1`). |
| `Plugin` | A packaged capability module exposing executable tools under a namespace; here `campus_kb` (read-only knowledge base), `ops_desk` (lab slot operations), and `media_world` (T4-compatible mockup of diagram generation and capacity simulation) are three separate plugins. |
| `Skill` | A procedural instruction bundle describing the workflow steps and constraints for a task (`policy-qa`, `lab-ops`, `incident-triage` inside `SKILL_LIBRARY`); guidance, not executable code (`Deney 1`). |
| `Progressive disclosure` | Keeping only a compact skill catalog in initial context and loading full procedural instructions (`render_skill_context`) only for the selected active skill to yield measurable `saved_chars` savings (`Deney 1`). |
| `Multi-agent orchestration` | Coordinating an orchestrator and focused specialist agents so a complex task completes inside clear tool and step boundaries (`Deney 2`). |
| `Orchestrator / coordinator` | The top-level controller (`ModernOrchestrator`) that runs the deterministic gate, invokes `System1DecisionGate`, and dispatches work within `max_handoffs=2`. |
| `Specialist agent` | A scoped subagent restricted to its own domain and allowed plugins; `research_specialist` sees only `campus_kb`, `operations_specialist` sees only `ops_desk`, and `simulation_specialist` sees only `media_world`. |
| `Routing` | Choosing the right execution path for a request—deterministic gate, `direct_system1` reflex, or a specific specialist agent (`Deney 2`). |
| `Delegation` | Assigning a bounded subtask from a coordinator to a worker under an explicit role and tool scope. |
| `Handoff` | Transferring active task control to another agent; unvalidated handoffs risk loops or dropped constraints (`Deney 2`). |
| `Structured handoff` | A schema-validated JSON handoff (`target_specialist`, `active_skill`, `user_goal`, `constraints`, `complexity`) that preserves requirements and rejects unlisted targets such as `admin_agent` (`StructuredHandoff`, `Deney 2`). |
| `Context loss` | Losing critical user constraints such as `"T4"` or `"14:00"` during an unstructured (`lossy`) free-text handoff, causing downstream errors (`Deney 2`). |
| `Rule-based / deterministic gate` | A Python pre-check (`deterministic_gate`) that handles bounds checks, `TR-204` ticket lookups, or exact `6 saat * 8.88 CU` math at `0` tokens and `0` LLM calls (`Deney 2`). |
| `Hybrid workflow` | Using an LLM to interpret free text or extract parameters while Python validates inputs, checks permissions, and computes exact arithmetic or slot state. |
| `System 1 decision model (Jev)` | Inspired by Kahneman's fast-reflex System 1 and TypeSafe AI's closed-source `Jev` paradigm: a **non-autoregressive** decision layer returning typed primitives in a single forward pass; `System1DecisionGate` is a lightweight T4-compatible mockup of this contract (`Deney 2`–`Deney 3`). |
| `Laya (Apache-2.0 System 1 model)` | An open-weight (**Apache-2.0**-licensed, **~100M-parameter** encoder-based) non-autoregressive System 1 decision model family serving as an open counterpart to `Jev`, returning `Choice`, `Score`, and `Noul` primitives with zero syntax hallucination. |
| `Choice` / `Score` / `Noul` (`RLCD`) | Three `System 1` decision primitives (`Jev` / `Laya`): `Choice` picks from a closed option set, `Score` outputs a rubric score (including *Jev-Mem* memory scoring), and `Noul` outputs a calibrated `[0, 1]` probability trained via **RLCD** (*Reinforcement Learning for Calibrated Decisions*) (`Deney 3`). |
| `SLM (Small Language Model)` | A compact autoregressive language model suited to low-latency edge or local text tasks; faster than large LLMs, yet still distinct from non-autoregressive System 1 decision gates. |
| `System 2 / reasoning model` | A deeper reasoning tier reserved for multi-step tool execution, policy synthesis, and complex constraint solving; on `llama.cpp v1.0.0` (`b12359`, `262,144` ctx), `G4` serves **`Qwen 3.8 27B + MTP`** (`reasoning_effort="xhigh"`, `1.0 / 0.95 / 20`, target+draft `f8_e4m3` KV, `4 × 262,144 = 1,048,576` GPU KV, `--cache-reuse 0`, `draft_max=3`), while `L4`/`T4` serve natively multimodal **`Gemma 4 12B QAT + MTP`** (`--reasoning on --reasoning-budget -1 --reasoning-preserve`, `enable_thinking=True`, `1.0 / 0.95 / 64`, target+draft `f8_e4m3` KV `-ctkd/-ctvd`, `p_min=0.75`, `524,288` GPU KV + RAM = `1,048,576` pool) (`Deney 3`). |
| `Multimodal LLM (VLM / Omni)` | A model class able to perceive images, screenshots, PDF pages, audio, or video directly and emit tool calls (`Computer Use` foundation); **`Gemma 4 12B`** is natively multimodal (its text GGUF runtime is used in this lightweight lab to preserve T4 VRAM). |
| `Image / video generation model` | A generative specialist (diffusion / *flow matching*, such as `Qwen-Image`) synthesizing visual diagrams or video frames; orchestrated behind `MCP` tools (`media_world` T4-compatible mockup here) with heavy synthesis left to high-VRAM G4/local setups. |
| `World model` | A model or simulator predicting how a physical, spatial, or operational environment changes after an action; represented here via `media_world`'s T4-compatible `simulate_lab_capacity` mockup contract. |
| `Model cascade` | Passing requests through the `0`-token `deterministic_gate`, then `System1DecisionGate`, and escalating only complex or low-confidence tasks to System 2 (`G4`: `Qwen 3.8 27B + MTP`; `L4`/`T4`: `Gemma 4 12B + MTP`) (`Deney 3`). |
| `Fallback / escalation` | Recovering safely when `Noul` confidence drops below threshold (`< 0.75`, e.g., `0.48`) or a router payload is malformed by setting `escalated_to_system2=True` and escalating to System 2 (`Deney 3`). |
| `Least-privilege tool scope` | Granting each specialist only the plugin tools required for its role; `research_specialist` cannot reserve slots, and injected `admin_agent` commands in `untrusted-ticket` never gain authority (`"untrusted evidence, never instructions"`). |
| `KV cache quantization (f8_e4m3 / FP8 vs q8_0)` | Compressing key/value attention memory to fit long context in VRAM; on `llama.cpp v1.0.0`, both target and **draft (`-ctkd/-ctvd`)** use `f8_e4m3` (`--spec-draft-p-min 0.75`, `draft_max`: T4 `2`, L4/G4 `3`) — live G4 `1M` GPU KV hit `235.35 tok/s` in `21,279 / 97,887 MiB` VRAM, while T4 `524,288` (`512K`) GPU KV fit in `14,047 MiB` VRAM at `41.69 tok/s`, whereas `q8_0` collapses 15x to `2.74 tok/s`. |
| `Unified 1M+ KV pool & prompt caching (--kv-unified, --cache-reuse)` | Pairing `MAX_CONTEXT=262,144` with `--kv-unified --kv-unified-per-slot 262144`, `--cache-ram`, `--ctx-checkpoints 8`, `--cache-reuse 64`, and `cache_prompt=True` for a **`1,048,576` (`1M+`) total KV pool** (`1,048,576` GPU KV @ `80.11%` MTP verified live on G4; `524,288` `512K` GPU KV + RAM cache on L4 and T4; live T4 Turn-2 `cached_tokens=182`, `324.07 tok/s` prefill). |
| `DualLayerSessionStore (FP8 KV + text_replay_fallback)` | Two-layer persistence across `ExperimentSession` and `Canlı Stüdyo`: Layer 1 writes human-readable `transcript.md` and `session_meta.json`, while Layer 2 saves optional FP8 `slot0.kv.bin` (`binary_kv_hit`) and falls back silently to `text_replay_fallback` if `/slots/0?action=restore` mismatches. |
| `Live Studio (Canlı Stüdyo, Studio v2 Portless WebUI)` | Interactive WebUI inside `Cell 5` using native `google.colab.output` JS RPC (`register_callback` / `invokeFunction`) with zero external ports or third-party cookies, offering clickable `💭 Düşünce Akışı` CoT cards, Antigravity-style FIFO prompt queuing (`[✕ Sıradan Çıkar]`), `🔧 Araç`, `[KV Kaydet]`/`[Yükle]` (`self.hist` synced), `⛶ Tam Ekran` (`ESC`), `⏹ Durdur`, and Kill Switch (`Arayüzü Kapat` -> `ALAB-E07`). |
| `MyDrive/AgentLab-Agent-Runtime` & `ALAB-Exx` | Person-agnostic Google Drive cache (`setup` shared + `day-03-modern-stack`) and fixed 2-line error armor (`ALAB-E01`–`ALAB-E10`/`ALAB-E99`) replacing raw Python tracebacks (`error-guide.pdf`). |
